# Project Memory — DeepSeek Harness (`dsh`)

Reference map of the whole repository as observed on `master` (HEAD `0d1f5000`, release `0.1.6-alpha.1`, clean tree). For standing agent orders see [AGENTS.md](../AGENTS.md); for the ordered runtime map see [architecture.md](architecture.md); for package authority see [packages/README.md](../packages/README.md).

## Identity

`dsh` is an all-plugin Cordis agent harness (developer preview, pre-stable APIs). Run from source with `pnpm install && pnpm run build && pnpm dsh web` (`http://127.0.0.1:3080`), or distributed as `npx @deepseek-ai/dsh web`. Engines: `node ^22.19 || >=24`, `pnpm@11.7.0`.

## Composition and turn flow

A running `dsh` is a plugin tree composed onto an empty entry list in this order: profile bundles, profile `cordis.patch.yml`, home-level patch, `--patch` overlay. Shipped profiles are `web`, `headless`, `sdk`, `sdk-minimal`, `acp`; `dsh-base` is the shared first layer of all but `sdk-minimal`, which owns its complete standalone tree. Only `dsh` profiles launch supported Node apps (`dsh web`, `--profile headless|sdk|sdk-minimal|acp`); package bins, demos, and SDK argv escapes are forbidden launchers. A step is one model request plus its tool calls; a turn is zero or more steps framed by `turn/start` and `turn/end`. The loop path is `agent/pre-step` (waterfall, must call `next()`) → `step/start` → `agent/request` + `prepareCall()` → `llm/stream` → `assistant/message|attempt` → `tools/pre-execute|execute|post-execute` → `step/end` → `agent/turn-stopping` (serial) → `turn/end`. Model-visible means logged: every model input must be reconstructable from the session log, and new model-visible input requires a session event. A capability seam is the complete Service Definition plus Service Provider plus Consumer triple, never one role alone.

## Repository layout

`vendor/` holds pinned vendored Cordis sources rescoped to `@deepseek-ai/*` (see [vendor/README.md](../vendor/README.md)). `packages/` holds 284 `@deepseek-ai/dsh-*` workspaces in 52 groups (see [packages/README.md](../packages/README.md)). `python/` holds the Python SDK plus platform runtime wheel (see [python/README.md](../python/README.md)). `native/system` holds `@deepseek-ai/node-addon-system` sources (`landlock-run`, `flock`) (see [native/README.md](../native/README.md)). `apps/cli` is the only supported Node launcher; `apps/desktop` is the Electron shell; `apps/desktop-host` is its private host; `apps/web` builds the served frontend. `benchmarks/` holds per-user-path performance gates; `snapshots/` holds committed replay corpora (`acp/`, `sdk/`, `session/`, `web/`); `scripts/` holds ~250 shell-free gates (`verify-*`, `gen-*`, coverage, persistence, pairing); `website/` is a VitePress projection adapter with no authored content; `.agents/` holds decision notes and reusable skills; `docs/` holds tiered documentation plus generated catalogs that must not be hand-edited.

## Package map (52 groups)

Execution: `shell/` owns the executor seam plus bash/pwsh local/sandboxed implementations and model tools (`ctx.shell`); `subprocess/` owns child-process management; `ssh/` owns shared POSIX connections with paired fs/subprocess/sandbox providers; `terminal/` owns persistent PTYs; `sandbox/` owns confinement backends; `fs/` owns governed filesystem access plus `read/write/edit/glob/grep/str_replace_editor` tools (`ctx.fs`); `lsp/` owns stdio language-server access. Durability: `session/` owns persistence seam plus JSONL backend, adjacent `vN→vN+1` migration codecs, checkpoint policy, projection seam plus cache/stats/outline, log-backed titles, and telemetry; `session-query/` owns retrieval and export; `storage/` owns non-session JSON/SQLite backends; `attachment/` owns durable images; `spill/` owns text spill; `workspace/` owns workspace entities. Model context and capabilities: `context/` (instructions, file/session references, time, tmux), `skill/`, `mcp/`, `web/` (fetch plus DeepSeek/Exa/Perplexity search), `computer-use/`, `browser-use/`, `jobs/`, `workflow/` (engine plus `workflow`/`ralph` tools), `subagent/` (in-process fork/spawn plus ACP/Claude/Codex/SDK backends), `compaction/`, `ptc-runtime/`, `typert/`. Collaboration: `interaction/` (commands, approvals, permissions, ask-user/questions), `todo/`, `plan/`, `goal/`, `schedule/`, `feedback/`, `identity/`, `preset/`, `guard/`, `extensions/` (runtime self-modification), `hooks/` (Claude Code/Codex bridges), `webhook/`. Product planes: `api/` (typed remote BFF), `settings/`, `credentials/`, `boot/` (shared app-bin glue, never loaded as plugins), `bundle/` (installable profile patch layers: `base`, `web-app`, `headless`, `sdk-app`, `sdk-minimal`, `acp-app`), `sdk/` (JSON-RPC protocol plus TS client/server), `acp/` (automation-only server), `host/` (HTTP host half), `client/` (53 browser-half packages: boot, transport, store, slots/renderer, conversation/chat/trajectory, sidebar/workspace, model/jobs/plan/goal/schedule/preset/permissions, settings). Support: `util/` (zero-dependency shared helpers including `Branded<B>`), `test-support/`, `runtime-diagnostics/`, `experimental/` (pre-stable prototypes, public by default with explicit private exceptions).

## Periphery details

`vendor/` pins 9 packages (`cosmokit`, `schemastery`, `cordis`, `loader`, `include`, `group`, `timer`, `hmr`, `logger-console`) with 19 logged local modifications and a documented sync procedure. `python/sdk` exposes lazy `DeepSeekHarness(dsh_home, cwd, provider, model)` over stdio NDJSON JSON-RPC with `sdk` (full) and `sdk-minimal` profiles plus ordered patch overlays; `python/sdk-runtime` ships platform wheels embedding `dsh` so no system Node is required (linux x64/arm64, macOS arm64/x64, windows x64). `native/system` ships musl-static `landlock-run` on Linux plus POSIX `flock`, Node-API v8 only. `apps/cli` owns profile composition and the `desktop` name reservation; `apps/desktop` pins Electron identity to the exact `@deepseek-ai/dsh` version, bundles upstream Node plus pnpm, serves UI over `dsh-app://` with no listening port, and supports macOS arm64/x64 plus Windows x64 only. `benchmarks/` runs `*.bench.ts` (Host) and `*.bench.client.ts` (Client) workers on built `lib/` with reviewed synthetic inputs and constant budgets. `snapshots/` replays `session[.vN].jsonl` parents plus ordinal children, selects the numerically highest generation, and never renames committed generations. `scripts/` owns freshness-gated generators (`config/tool/cordis/persistence-catalogs`, `module-graph`, `tsconfig-paths`) and reviewers (`cordis-config`, `client-i18n`, `export-jsdoc`, `package-invariants`, `runtime-closure`, `doc-budgets/links`, `translation-pairing`). `.agents/notes/` owns decision records by lifecycle (`proposed/`, `implemented/`, `rejected/`, frozen `archived/`) and class (`feature`, `bug-fix`, `simplification`, `architecture`, `process`, `testing`); `.agents/skills/` owns 13 reusable workflows including `dsh-doc`, `dsh-prose-standard`, `dsh-pre-push-checks`, and `dsh-code-review`.

## Tooling, tests, docs

Root `package.json` is private ESM with no runtime dependencies; workspaces are `vendor/*`, `packages/*/*`, `native/system` (+ platform packages), `apps/*`, `website`. TypeScript uses a solution-only root plus explicit Host/Client faces (`tsconfig.host.json`, `tsconfig.client.json`) because both merge Cordis `Context` under the same keys; static gates resolve workspace imports to `src` via generated `paths`, while subprocess/config gates consume built `lib/` explicitly. Vitest suites are `test` (unit), `test:coverage` (per-file 100% gate on `packages/*/*/src`), `test:e2e` (real APIs, self-skips without `DEEPSEEK_API_KEY`), `test:expected` (owner-local), `test:snapshot` (keyless replay, `:record`/`:refresh` need a key), plus web/bench lanes. Documentation follows one-home-per-fact tiers (see [docs/AGENTS.md](AGENTS.md)): current-state prose, one physical line per paragraph, bilingual EN+ZH pairs recorded in `.i18n.yaml`, compilable `ts` pastes, word budgets enforced by `verify-doc-budgets`. New English-only pages may trip pairing/budget gates until their Chinese counterpart and records are added through `dsh-translate-docs` on explicit request.

## Working entry points

Read [architecture.md](architecture.md) before changing `packages/`; then the owning group README, its subsystem page under [subsystems/](subsystems/README.md), and linked Agent Notes. Daily loop: smallest checks covering the surface (`doc-sync` for docs, focused behavior tests, built smokes for published paths, real-API e2e for providers) selected via `.agents/skills/dsh-pre-push-checks/SKILL.md`; CI owns the exhaustive matrix. Smoke a change with `pnpm dsh --profile headless "task"` (needs `DEEPSEEK_API_KEY`) after `pnpm run build`. Never commit credentials; `DEEPSEEK_API_KEY`, optional `DEEPSEEK_BASE_URL`, and root `.env` feed real-API runs.

# Agent Note: E2B cloud execution providers with local/cloud profile switch

Status: proposed

[English](2026-09-18-e2b-cloud-execution-providers.md) | 中文

## Problem

本地机器资源有限的操作者需要将脚本、测试、预览和命令执行放到更有余量的地方运行，而另一些操作者则希望一切保留在自己的硬件上。单一硬编码的执行世界无法同时服务两者：文件所在位置和进程运行位置的选择属于部署范畴，且必须按用户可切换，而无需分叉产品。
[E2B 移除决策](../simplification/2026-09-11-remove-e2b-providers.md)退役了此前的托管沙箱集成，因为所锁定的 SDK 未为 PTC 控制流量提供额外描述符传输，并在宿主机上保留完整的 stdout/stderr，同时该决策列明了明确的重引入条件。[POSIX SSH 提供者](../architecture/2026-09-11-posix-ssh-runtime.md)覆盖拥有 SSH 主机的部署，但不覆盖希望使用以 API 令牌计费的托管云沙箱的部署。目前没有任何组合为后者提供本地/云切换。

## Proposal

以镜像 SSH 家族形态的受控提供者家族重引入 E2B：一个连接包加上共享同一 E2B 沙箱世界的文件系统、子进程和沙箱提供者，Harness、凭证、模型传输和会话持久化保留在宿主机。本地/云切换发生在组合时，绝不在提供者内部作运行时分支：默认画像挂载本地家族，而要求 `E2B_API_KEY` 的可选 E2B 覆盖层（画像或 `--patch` 文件）为该次运行替换整个执行世界。第一阶段排除 E2B 上的 PTC Node 执行（尚无 fd7 控制通道），以提供者拥有的原始字节尾部快照界定收集输出，并将连接丢失视为失效而不重放可能已执行的程序。
新 `packages/e2b/` 分组下计划的包为 `e2b`（`ctx.e2b` 上的连接生命周期）、`fs-e2b`（注册于 `ctx.fs`）、`subprocess-e2b`（注册于 `ctx.subprocess`）和 `sandbox-e2b`（注册于 `ctx.sandbox` 并携带远端文件效应强制事实）。各提供者遵循[可移植执行世界决策](../architecture/2026-07-28-portable-execution-world-consumers.md)，拥有 E2B 世界的路径转换、可执行查找、普通流、终端分配和受管清理；消费者保留工具语义、策略与呈现不变。

## Provider topology

`e2b` 连接包拥有沙箱预留与服务端超时生命周期；不在沙箱内安装辅助程序，也不运行心跳，因为 E2B 两者都不需要。文件系统、子进程和沙箱提供者共享该连接，并描述 E2B 世界路径而不加本地/远端元数据标志。终端分配、写入、前台检查与信号保留其异步 Promise 契约，因此共享接口无需 E2B 专用工具。E2B 作为整体世界替换注册，绝不作为 `ctx.sandbox` 后端：confinement 仅限同世界，被强制的事实是沙箱边界本身，而非世界内路径围栏。

## Composition and switching

已发布的画像保留本地提供者为默认。`e2b` bundle（或补丁覆盖层）以四个 E2B 行替换本地行，因此 `dsh --profile headless` 在本地运行，而 `dsh --profile headless-e2b`（或 `--patch e2b.yml`）在云沙箱中运行同一任务。缺失 `E2B_API_KEY` 在加载时大声失败；已配置的密钥绝不泄漏到程序环境。如需按会话区分能力，继续使用带 `isolate` 域的 agent preset。headless 组合先行采用该安排；具宿主机文件系统假设的 Web 工作区视图需各自集成后才能跟进。

## Transport bounds

收集的 stdout/stderr 以原始字节尾部快照发布，携带全流字节偏移，提供者以自有的保留输出存储作溢出承接，而不在宿主机累积无界内存。管理 RPC 期限、消费者执行期限与清理各归其主。每个流预留在其负载启动前创建，关闭按通道精确执行，取消绝不重放 Results 不明的变更。

## Alternatives considered

**保持 E2B 退役，仅以 SSH 服务远端执行。** 这避免了第二个远端传输及其 SDK 依赖，但使没有 SSH 主机、且明确选择托管云沙箱的操作者（正是本提案服务的人群）无支持路径。
**在一个提供者后运行时切换执行世界。** 运行时 `if 本地/else 云` 分支把部署选择藏进 `run()`，违反显式解析规则与每组合单执行器不变量；画像组合本就拥有该开关。
**将 E2B 注册为 `ctx.sandbox` 后端。** 沙箱只约束共享宿主内核与文件系统的同世界进程；云沙箱整体替换文件系统、子进程与沙箱能力，后端注册会错置路径、查找与清理的所有权。
**将整个 Harness 搬入云沙箱。** 那是把模型凭证、会话存储与插件状态随执行一起迁移，而非为既有能力提供远端实现；属于另一种部署模型，而非提供者家族。

## Acceptance criteria

本地画像与 E2B 画像以相同的 headless 任务产出除执行世界路径外一致的模型可见输出。缺失凭证在任何运行前大声失败。限界尾部、预留取消、精确关闭、无重放断开等行为由源码与构建画像上的 REAL-composition 测试锁定，并附组合形态的无密钥录制会话快照。E2B 实况检查仅对显式配置的一次性沙箱运行；无密钥 CI 绝不置备。移除决策保持有效并互链，作为其拥有的已退役实现记录。

## Risks

E2B SDK 可能仍缺合适的控制传输，那将使 PTC Node 执行长期处于范围之外，家族止于文件系统、子进程、终端与 LSP 用途。SDK 输出保留行为可能迫使另建鉴权流设计，使家族变成移除时所拒绝的远端传输工程。第二个远端家族使传输、预留与断开验证义务翻倍。云执行还带来本地运行从不需要的凭证处理、网络策略与成本控制。
